📌 What Did We Build?📌 Humne Kya Banaya?

A file upload feature on /help-chat page that uploads images to ImageKit CDN. The upload is a 2-step process — first get a signed JWT token from ImageKit, then upload the file using that token. Because ImageKit's signature endpoint rejects requests from any origin other than https://imagekit.io, we use a proxy that runs on the server side (Vite in dev, Netlify Function in production). /help-chat page par ek file upload feature jo images ko ImageKit CDN par upload karta hai. Upload 2-step process hai — pehle ImageKit se signed JWT token lo, phir us token se file upload karo. Kyunki ImageKit ka signature endpoint https://imagekit.io ke alawa kisi origin se request reject karta hai, hum ek proxy use karte hain jo server side par run karta hai (dev mein Vite, production mein Netlify Function).

Local Dev — How the Vite Proxy WorksLocal Dev — Vite Proxy Kaise Kaam Karta Hai

The browser's Origin header always reflects the real page origin. JavaScript cannot override it. So a fetch from localhost:5173 always sends Origin: http://localhost:5173, which ImageKit rejects. The Vite proxy runs inside Node.js on the dev server — Node.js is not a browser, so it can set any header it wants. Browser ka Origin header hamesha real page origin reflect karta hai. JavaScript isse override nahi kar sakta. To localhost:5173 se fetch hamesha Origin: http://localhost:5173 bhejta hai, jo ImageKit reject karta hai. Vite proxy dev server par Node.js ke andar run karta hai — Node.js browser nahi hai, isliye wo koi bhi header set kar sakta hai.

vite.config.ts — ikSignatureProxyPlugin() When browser calls POST /ik-signature ↓ Vite middleware intercepts (same origin — no CORS) ↓ Reads from request: csrf-token header → forwards as-is x-ik-cookie header → used as Cookie header request body (JSON) → forwards as-is ↓ Node.js https.request → imagekit.io origin: https://imagekit.io ← SPOOFED ✅ referer: https://imagekit.io/dashboard/media-library ← SPOOFED ✅ cookie: connect.sid=...; _csrf=... ← from x-ik-cookie ✅ csrf-token: K3DnTkCR-... ← forwarded ✅ ↓ imagekit.io → 200 OK → { "token": "eyJhbGci..." } ↓ Vite returns JSON to browser

CSRF Token — What It Is & When to Change ItCSRF Token — Kya Hai & Kab Badlein

What Is It?Kya Hai?

CSRF = Cross-Site Request Forgery. ImageKit's internal signature endpoint uses a CSRF token to verify that API calls come from their own dashboard, not from an external site. The token is a string generated by imagekit.io's server and tied to your login session. CSRF = Cross-Site Request Forgery. ImageKit ka internal signature endpoint CSRF token use karta hai ye verify karne ke liye ki API calls unke apne dashboard se aa rahi hain, kisi external site se nahi. Token ek string hai jo imagekit.io ke server se generate hoti hai aur tumhare login session se tied hai.

ThingCheezWhere It LivesKahan HaiHow Long ValidKitna Valid
csrf-token header valueHardcoded in HelpChatPage.tsx as IK_CSRF_TOKENHelpChatPage.tsx mein IK_CSRF_TOKEN ke roop mein hardcodedUntil session changes (days/weeks)
_csrf cookieSet by imagekit.io — visible in DevTools Cookies. You paste this as part of x-ik-cookie.imagekit.io se set — DevTools Cookies mein dikhta hai. Ise x-ik-cookie ke part ke roop mein paste karo.Long-lived (months)
ℹ️ The csrf-token header value and the _csrf cookie are related but NOT the same string. imagekit.io's server derives the header value from the cookie using a secret. You only need to grab the header value from the Network tab. csrf-token header value aur _csrf cookie related hain lekin SAME string nahi. imagekit.io ka server cookie se ek secret use karke header value derive karta hai. Tumhe sirf Network tab se header value grab karni hai.

When Does It Need Updating?Kab Update Karna Padega?

  • You get 403 {"error": "Invalid CSRF Token"} from the signature APISignature API se 403 {"error": "Invalid CSRF Token"} mile
  • You logged out of imagekit.io and logged back inimagekit.io se logout karke phir login kiya
  • Your imagekit.io session expired (usually after days of inactivity)imagekit.io session expire ho gayi (usually inactivity ke kaafi dino baad)

Session Cookie — How to Get ItSession Cookie — Kaise Lo

Why Do We Need Cookies?Cookies Kyun Chahiye?

ImageKit's signature endpoint requires you to be logged in. Your browser proves you're logged in via session cookies (connect.sid = session ID, _csrf = CSRF seed). These cookies are domain-locked to imagekit.io — the browser won't send them to localhost or Netlify. So the user must manually paste them. ImageKit ka signature endpoint require karta hai ki aap logged in ho. Browser session cookies se prove karta hai ki aap logged in ho (connect.sid = session ID, _csrf = CSRF seed). Ye cookies imagekit.io domain par lock hain — browser inhe localhost ya Netlify par nahi bhejega. Isliye user ko manually paste karna padta hai.
