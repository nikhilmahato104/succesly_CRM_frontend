PWA & iOS Safari
Optimization Guide

Succesly Admin May 2026 React + Vite iOS Safari 15+

1What is a PWA?

A Progressive Web App (PWA) is a website that installs on the phone and behaves exactly like a native app — no App Store required.

When a user opens the app in iPhone Safari and taps "Add to Home Screen", the browser installs it. After that:

  • It opens without the Safari browser bar — no address bar, no tab bar at the bottom.
  • It looks and feels like a native iPhone app (like Twitter, Instagram, Linear, Notion).
  • It has its own icon on the home screen with a custom name.
  • It shows a splash/launch screen while loading (instead of a white flash).
  • It can work offline when a service worker is configured.
  • The iPhone status bar (time, battery, signal) blends seamlessly into the app.
ℹ️

For a PWA to work on iPhone you need 4 things: correct meta tags in HTML, a manifest.json, a service worker (sw.js), and safe-area CSS. All four are covered in this guide.

2Safe Area & viewport-fit=cover

The Problem

iPhones have physical areas the screen content must never hide behind:

  • Notch / Dynamic Island at the top (camera + sensors)
  • Home Indicator at the bottom (the thin swipe-up bar)
  • Side bezels in landscape on notched iPhones

By default, Safari keeps content inside these safe zones and shows white gaps around the edges. The app background cannot fill the full screen. This looks non-native.

The Fix: viewport-fit=cover

<meta name="viewport"
      content="width=device-width, initial-scale=1.0, viewport-fit=cover" />

This tells Safari: "Let my content go behind the notch and home indicator — I will handle the padding myself."

Now the shell background color fills the entire screen including behind the Dynamic Island and home indicator bar. This is the premium, native feel.

CSS Environment Variables

Once viewport-fit=cover is set, the browser exposes 4 CSS variables:

VariableWhat it representsExample value (iPhone 15 Pro)
env(safe-area-inset-top)Height of Dynamic Island / notch59px
env(safe-area-inset-bottom)Height of home indicator bar34px
env(safe-area-inset-left)Side inset in landscape0px (portrait)
env(safe-area-inset-right)Side inset in landscape0px (portrait)

On devices without a notch, all values are 0 — so the fallback (6px gutter) still applies. We use max() to handle both cases:

.dashboard-shell {
  padding-top:    max(6px, calc(env(safe-area-inset-top)    + 2px));
  padding-bottom: max(6px, calc(env(safe-area-inset-bottom) + 2px));
  padding-left:   max(6px, calc(env(safe-area-inset-left)   + 2px));
  padding-right:  max(6px, calc(env(safe-area-inset-right)  + 2px));
}

⚠️

iOS ignores the manifest icons array. For Apple devices you must use <link rel="apple-touch-icon"> tags in HTML. Both approaches are included in this project.

public/sw.js

The Service Worker. A JavaScript file that runs in the background, separate from the page. It intercepts all network requests and can serve cached responses — enabling offline support and faster repeat visits.

Caching Strategies Used

StrategyUsed ForWhy
Cache-firstJS, CSS, fonts, imagesVite adds a content-hash to filenames (e.g. main-a3f9c2.js). These are immutable — cached version is always correct and loads instantly
Network-firstHTML / page navigationsAlways try to get fresh content. Fall back to cached index.html when offline (SPA routing still works)
Network-onlyAPI callsLive data must always come from the server. Never serve stale API responses

Cache Version Bumping

// In public/sw.js — bump this when deploying a breaking change:
const CACHE_VERSION = 'v1'; // → change to 'v2' on next major deploy

// This causes all caches named 'np-admin-static-v1' to be deleted
// on the next visit, forcing users to download fresh assets.

public/icons/icon.svg

The source icon SVG — a black rounded square with a white "N" letter, matching the TopBar logo mark. This is the source file used to generate all PNG icon sizes. The SVG itself is used as the browser tab favicon on modern browsers that support SVG favicons.

src/hooks/useIOSViewport.ts

A React hook that fixes two persistent iOS Safari bugs.

Bug 1 — Address Bar Height Problem

100vh in CSS includes the space behind Safari's retractable address bar. When the user scrolls down and the address bar hides, the viewport gets taller — causing layout jumps. The fix is to use window.visualViewport.height (the actual visible height) and store it in a CSS custom property --vh:

const setVh = () => {
  const height = window.visualViewport
    ? window.visualViewport.height
    : window.innerHeight;
  document.documentElement.style.setProperty('--vh', `${height * 0.01}px`);
};

Bug 2 — Keyboard Hides Content

When the iOS keyboard opens, window.innerHeight does not shrink (an iOS-only quirk) but window.visualViewport.height does. The hook listens to visualViewport.resize events and updates --vh so layouts don't get buried under the keyboard.

lockBodyScroll() Export

iOS Safari ignores overflow: hidden on <body> when a modal is open — the background page keeps scrolling. The correct fix:

// Instead of: document.body.style.overflow = 'hidden'  ← broken on iOS

const scrollY = window.scrollY;
document.body.style.position = 'fixed';
document.body.style.top      = `-${scrollY}px`; // preserve position
document.body.style.width    = '100%';

// On modal close — restore:
document.body.style.position = '';
window.scrollTo(0, scrollY);   // jump back to where user was

A large iOS Foundation section was added at the very top, before the design tokens. Here is every rule and the exact problem it solves:

html & body Base Rules

Input Zoom Prevention (iOS-only Selector)

/*
  @supports (-webkit-touch-callout: none) only matches iOS & iPadOS Safari.
  It does NOT match Android Chrome or desktop Safari — so this only
  applies on iPhone and iPad. Nothing on desktop is changed.
*/
@supports (-webkit-touch-callout: none) {
  input, textarea, select {
    font-size: 16px !important; /* iOS zooms when < 16px. This prevents it */
  }
}

Dashboard Shell — Safe Area Aware Height & Padding

.dashboard-shell {
  height: 100svh; /* svh = Small Viewport Height (excludes Safari address bar) */
  height: 100dvh; /* dvh = Dynamic Viewport Height — best option, overrides svh */

  /* min 6px gutter on desktop, grows with the notch/home-indicator size */
  padding: max(6px, calc(env(safe-area-inset-top)    + 2px))
           max(6px, calc(env(safe-area-inset-right)  + 2px))
           max(6px, calc(env(safe-area-inset-bottom) + 2px))
           max(6px, calc(env(safe-area-inset-left)   + 2px));
}

@media (max-width: 1023px) {
  .dashboard-shell {
    /* Mobile: no side padding — edge-to-edge like a native app */
    padding: env(safe-area-inset-top) 0 env(safe-area-inset-bottom) 0;
  }
}

Mobile Content Card — Edge-to-Edge

@media (max-width: 1023px) {
  .content-card {
    border-radius: 0 !important; /* Native apps don't float inside a rounded card */
    border-left:   none !important;
    border-right:  none !important;
  }
}

Scroll Improvements

.sc-scrollbar {
  -webkit-overflow-scrolling: touch; /* Legacy momentum scroll (harmless on modern iOS) */
  overscroll-behavior:        contain; /* Scroll doesn't escape to the page */
  will-change: scroll-position; /* GPU layer — prevents checkerboard flicker on iOS */
}

Touch Target Sizing

/* pointer: coarse = touch screens. pointer: fine = mouse/trackpad */
@media (max-width: 1023px) and (pointer: coarse) {
  button, [role="button"] {
    min-height: 44px; /* Apple HIG minimum tap target (44×44pt) */
    min-width:  44px;
  }
}

src/hooks/useDarkMode.ts

Added updateThemeColorMeta() — called every time the user toggles dark mode. It updates the <meta name="theme-color"> tag in real time so Safari's browser chrome and PWA status bar color changes immediately:

const updateThemeColorMeta = (dark: boolean) => {
  const metas = document.querySelectorAll('meta[name="theme-color"]');
  metas.forEach((meta) => {
    const media = meta.getAttribute("media") || "";
    if (media.includes("dark")) {
      meta.setAttribute("content", "#0d0d0d");
    } else {
      // light / no media — update to match current mode
      meta.setAttribute("content", dark ? "#0d0d0d" : "#ffffff");
    }
  });
};

src/templates/DashboardLayout.tsx

Three changes were made:

  1. Added useIOSViewport() hook call — runs once at the layout root, setting up the --vh variable and keyboard listeners.
  2. Outer div: removed inline height and padding, added className="dashboard-shell" — env() values inside inline React styles can behave inconsistently on older iOS. CSS classes are always reliable.
  3. Content card: added className="content-card" — allows the CSS to strip the rounded corners and side borders on mobile for an edge-to-edge native look.
// Before:
<div style={{ height: "100dvh", padding: "6px", ... }}>

// After:
<div className="dashboard-shell" style={{ overflow: "hidden", ... }}>

src/main.tsx

Service worker registration added. The import.meta.env.PROD guard is critical — it ensures the SW only runs in production builds. In development (npm run dev), the SW is skipped so Vite's Hot Module Replacement (HMR) works normally without being intercepted by the cache.

if ("serviceWorker" in navigator && import.meta.env.PROD) {
  window.addEventListener("load", () => {
    navigator.serviceWorker
      .register("/sw.js", { scope: "/" })
      .then((reg) => {
        // Check for SW updates every 60 minutes
        setInterval(() => reg.update(), 60 * 60 * 1000);
      });
  });
}

5How to Generate Icons

PNG icon files are required but cannot be generated automatically in the codebase. Use this one-time command after deployment setup:

# Install the generator tool globally
npm install -g pwa-asset-generator

# Generate all icon sizes from the SVG source
npx pwa-asset-generator public/icons/icon.svg public/icons \
  --background "#111111" \
  --padding "20%" \
  --manifest public/manifest.json \
  --index index.html
✅

This command automatically updates manifest.json with all icon paths and injects <link rel="apple-touch-icon"> tags into index.html. No manual editing needed.

What is a maskable icon? Android draws app icons in different shapes (circle, square, squircle) depending on the phone manufacturer's launcher. A maskable icon has extra padding on all sides (at least 10% safe zone) so the logo stays visible when Android clips it to any shape.

7How to Test on iPhone

Method 1 — Safari on Real iPhone (Essential)

  1. Run npm run build then deploy to any server (Netlify, Vercel, your server).
  2. Open the URL in Safari on iPhone (must be Safari — Chrome iOS cannot install PWAs).
  3. Tap the Share button (box with an up arrow at the bottom).
  4. Scroll down and tap "Add to Home Screen".
  5. Tap "Add".
  6. Close Safari completely (swipe up from bottom, swipe Safari off screen).
  7. Open the app from the home screen icon.

What to verify: No browser chrome (no address bar), status bar text overlays the app, app icon shows correctly, splash screen appears on cold launch, no white gaps around notch or home indicator.

Method 2 — Safari Remote DevTools from Mac (Best for Debugging)

  1. On iPhone: Settings → Safari → Advanced → Web Inspector → turn ON.
  2. Connect iPhone to Mac via USB cable.
  3. On Mac: open Safari → Develop menu → [Your iPhone Name] → [Your page].
  4. Full Safari DevTools open — inspect DOM, read env() values, check network tab, debug JS.

To read the actual safe area values on the current device:

// Paste in Safari DevTools console on the iPhone:
const el = document.createElement('div');
el.style.cssText = 'position:fixed;padding:env(safe-area-inset-top) env(safe-area-inset-right) env(safe-area-inset-bottom) env(safe-area-inset-left)';
document.body.appendChild(el);
const s = getComputedStyle(el);
console.log({
  top:    s.paddingTop,
  right:  s.paddingRight,
  bottom: s.paddingBottom,
  left:   s.paddingLeft
});
document.body.removeChild(el);

Method 3 — Xcode Simulator (Mac only, no real device needed)

  1. Install Xcode from the Mac App Store.
  2. Open Xcode → menu → Open Developer Tool → Simulator.
  3. Choose an iPhone model (e.g. iPhone 15 Pro for Dynamic Island testing).
  4. Open Safari in the simulator and navigate to your dev server IP.

Testing Offline / Service Worker

  1. Open the installed PWA on iPhone and visit a few pages.
  2. Turn on Airplane Mode.
  3. Close and reopen the app from the home screen.
  4. Pages visited before should load from cache.
  5. API calls should fail (correct — they are network-only, never cached).

9Dark Mode & Theme Color

The app uses a custom dark mode toggle (not the OS system setting). When the user clicks the dark/light toggle in the profile dropdown, useDarkMode.ts both flips CSS variables and now also updates the browser chrome color instantly.

Why theme-color matters for PWA

The <meta name="theme-color"> tag controls:

  • Safari's browser tab area color when viewing the site normally
  • The status bar background when running as an installed PWA
  • The splash screen chrome color on Android

Without dynamic updates, the browser chrome stays white even when the app switches to dark mode — a jarring mismatch. With the updateThemeColorMeta() call, the color updates the moment the user toggles.

10Service Worker Deep Dive

Lifecycle

EventWhen it firesWhat our SW does
installFirst time SW is downloadedCalls skipWaiting() to activate immediately. Pre-caches / (index.html)
activateAfter install, when taking controlCalls clients.claim() to take control of open tabs. Deletes old cache versions
fetchEvery network request from the appIntercepts and applies the correct caching strategy (see table in Section 3)

How Updates Work

  1. You deploy a new version of the app (new JS/CSS files).
  2. User visits the site — browser downloads the new sw.js in the background.
  3. New SW enters "waiting" state while the old SW is still active.
  4. Because we call skipWaiting(), the new SW activates immediately.
  5. Old caches (previous version key) are deleted in the activate handler.
  6. User gets fresh assets on the next page navigation.
⚠️

Remember to bump CACHE_VERSION in public/sw.js when deploying a breaking change (e.g. renamed routes, changed API format). Change 'v1' → 'v2'. This forces all old caches to be cleared.
