Dark / Light Theme Transition

A Telegram-style circular reveal effect for switching between dark and light themes — a circle expands from the toggle button when going dark, and shrinks back to it when going light.

💡

This feature uses the browser's View Transitions API (Chrome / Edge 111+) with a CSS clip-path: circle() animation. Firefox falls back to a smooth CSS crossfade transition automatically.

Overview

When the user clicks the sun/moon pill toggle in the sidebar profile dropdown, the entire application theme switches with a circular wipe animation:

  • Light → Dark: a dark circle starts tiny at the click point and expands to fill the entire screen.
  • Dark → Light: the dark screen shrinks into a circle back to the click point, revealing the light theme underneath.

The animation is 750 ms by default with a smooth cubic-bezier(0.45, 0, 0.55, 1) easing (ease-in-out). You can change the speed — see the Changing Speed section.

What the Effect Looks Like

Light → Dark

A tiny dark circle appears at the exact position of the toggle click and grows outward until it covers the entire viewport.

🌙

CSS: ::view-transition-new(root) animates with theme-circle-expand keyframe.
Old (light) snapshot stays frozen underneath at z-index: 0.

Dark → Light

The dark screen shrinks into a circle that retreats to the toggle click point, revealing the light theme underneath.

☀️

CSS: ::view-transition-old(root) animates with theme-circle-shrink keyframe.
New (light) snapshot stays frozen underneath at z-index: 0.

Step-by-Step Flow

This is exactly what happens when the user clicks the toggle:

1

User clicks the pill toggle button

The button's onClick in ThemeToggle fires:
onClick={(e) => onToggle(e.clientX, e.clientY)}
e.clientX / e.clientY = exact pixel position of the click on screen.

2

useDarkMode receives the coordinates

toggleDarkMode(x, y) is called. Two CSS custom properties are set on <html>:
--vt-x: <x>px and --vt-y: <y>px
These are the center point of the circle animation.

3

Direction attribute is set

The hook sets data-theme-dir="to-dark" or "to-light" on <html>.
This tells the CSS which animation to play — expand or shrink.

4

Browser takes a BEFORE snapshot

document.startViewTransition(callback) is called.
The browser instantly screenshots the current page (old theme).

5

flushSync forces React to render the new theme NOW

Inside the callback, flushSync() is called with setIsDarkMode(next).
This makes React render synchronously — the .dark class is added/removed on <html> immediately.
Without flushSync: React batches the update and the browser sees identical before/after → no animation.

6

Browser takes an AFTER snapshot

Now the browser has two snapshots: old theme and new theme.
It stacks them and begins playing the CSS animations defined by ::view-transition-new(root) and ::view-transition-old(root).

7

clip-path circle animation plays

The circular wipe plays for 750 ms. When it finishes, the browser removes the transition pseudo-elements and the real new-theme page is visible.

CSS — Keyframes & Transition Rules

File: src/index.css — search for "Telegram-style circular theme reveal"

1. @keyframes theme-circle-expand

Used when going Light → Dark. The new (dark) page starts as a zero-radius circle and grows to cover the entire viewport.

/* Circle grows from click point (--vt-x, --vt-y) to fill the screen */
@keyframes theme-circle-expand {
  from { clip-path: circle(0px     at var(--vt-x) var(--vt-y)); }
  to   { clip-path: circle(200vmax at var(--vt-x) var(--vt-y)); }
}
  • 0px → invisible circle (nothing visible)
  • 200vmax → large enough to cover any screen (diagonal of 100vw×100vh is ~141vmax, 200vmax is safe)
  • var(--vt-x) var(--vt-y) → center of circle = toggle button click position

2. @keyframes theme-circle-shrink

Used when going Dark → Light. The old (dark) page starts as full-screen and shrinks to zero at the click point, revealing the light page underneath.

/* Circle shrinks from full screen back to click point */
@keyframes theme-circle-shrink {
  from { clip-path: circle(200vmax at var(--vt-x) var(--vt-y)); }
  to   { clip-path: circle(0px     at var(--vt-x) var(--vt-y)); }
}

3. ::view-transition-new(root) — Light → Dark

This pseudo-element represents the new (after) state of the page snapshot. For going dark, we expand it as a circle.

/* data-theme-dir="to-dark" is set by useDarkMode.ts before transition */
html[data-theme-dir="to-dark"]::view-transition-new(root) {
  animation: theme-circle-expand 750ms cubic-bezier(0.45, 0, 0.55, 1) forwards;
  z-index: 10;           /* sits on top of the old snapshot */
  mix-blend-mode: normal; /* no colour blending with old snapshot */
}
html[data-theme-dir="to-dark"]::view-transition-old(root) {
  animation: none;        /* old (light) page stays completely still */
  z-index: 0;
}

4. ::view-transition-old(root) — Dark → Light

For going light, we animate the old (before) state — the dark page — to shrink away.

/* data-theme-dir="to-light" is set by useDarkMode.ts before transition */
html[data-theme-dir="to-light"]::view-transition-old(root) {
  animation: theme-circle-shrink 750ms cubic-bezier(0.45, 0, 0.55, 1) forwards;
  z-index: 10;           /* dark overlay sits on top, shrinking away */
  mix-blend-mode: normal;
}
html[data-theme-dir="to-light"]::view-transition-new(root) {
  animation: none;        /* new (light) page already visible underneath */
  z-index: 0;
}

/* Disable browser's default cross-fade — only our circle animation runs */
::view-transition-group(root) {
  animation-duration: 0s;
}

useDarkMode Hook

File: src/organisms/SidebarV2/hooks/useDarkMode.ts

import { useState, useCallback, useEffect } from "react";
import { flushSync } from "react-dom";  // ← forces sync render inside transition

const toggleDarkMode = useCallback((x: number, y: number) => {

  // Function that React renders synchronously inside the transition callback
  const applyToggle = () => {
    flushSync(() => {
      setIsDarkMode(prev => {
        const next = !prev;
        document.documentElement.classList.toggle("dark", next);
        localStorage.setItem(STORAGE_KEYS.DARK_MODE, String(next));
        return next;
      });
    });
  };

  // ── View Transitions API path (Chrome / Edge 111+) ──────────────────
  if ("startViewTransition" in document) {
    document.documentElement.style.setProperty("--vt-x", `${x}px`);
    document.documentElement.style.setProperty("--vt-y", `${y}px`);
    document.documentElement.setAttribute(
      "data-theme-dir",
      !isDarkMode ? "to-dark" : "to-light"
    );
    (document as any).startViewTransition(applyToggle);
    return;
  }

  // ── Fallback: CSS crossfade (Firefox) ───────────────────────────────
  document.documentElement.classList.add("theme-switching");
  applyToggle();
  window.setTimeout(() => {
    document.documentElement.classList.remove("theme-switching");
  }, 420);

}, [isDarkMode]);

Why flushSync?

⚠️

Without flushSync, React batches the state update and doesn't render until after startViewTransition's callback has returned. The browser then captures two identical snapshots (both old theme), and the animation plays between two same images — you see nothing.

flushSync from react-dom forces React to commit the state update and re-render the DOM synchronously inside the callback. The browser then captures a real before/after diff and the circle animation is visible.

The data-theme-dir attribute

The CSS pseudo-elements ::view-transition-new(root) and ::view-transition-old(root) can't detect "which direction" the transition is going. We solve this with an HTML attribute:

Attribute valueDirectionWhich snapshot animatesAnimation
to-darkLight → Dark::view-transition-new (dark page)circle expands
to-lightDark → Light::view-transition-old (dark page)circle shrinks

Changing Animation Speed

Open src/index.css and find the two rules below. Change both durations to the same value to keep the expand and shrink in sync. 

/* Rule 1 — Light → Dark (expand) */
html[data-theme-dir="to-dark"]::view-transition-new(root) {
  animation: theme-circle-expand 750ms cubic-bezier(...) forwards;
  /*                               ↑ CHANGE THIS */
}

/* Rule 2 — Dark → Light (shrink) */
html[data-theme-dir="to-light"]::view-transition-old(root) {
  animation: theme-circle-shrink 750ms cubic-bezier(...) forwards;
  /*                                ↑ CHANGE THIS (keep same as Rule 1) */
}

500msFast
750ms✓ Default — smooth and comfortable
1000msSlow / cinematic
1500msVery slow / dramatic

Fallback — Firefox & Older Browsers

When "startViewTransition" in document is false, the hook adds class="theme-switching" to <html> for 420 ms while the theme changes. The CSS fallback rule applies smooth transitions to every element: 

/* src/index.css — search for "Smooth CSS fallback" */
html.theme-switching,
html.theme-switching * {
  transition:
    background-color 380ms cubic-bezier(0.4, 0, 0.2, 1),
    border-color     380ms cubic-bezier(0.4, 0, 0.2, 1),
    color            280ms cubic-bezier(0.4, 0, 0.2, 1) !important;
}

This gives a smooth crossfade in Firefox where every colour changes gradually instead of jumping.
